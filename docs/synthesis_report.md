## 3. 触发器与寄存器位宽对账

RTL 声明的寄存器共 292 位，综合后只有 227 个触发器。下面说明这 65 位差额的去向。

### 3.1 步骤

1. **列出 RTL 寄存器及声明位宽**（来自 `rtl/mac_pe.v`、`rtl/systolic_row.v`）：
   - 每个 PE：`w_reg` 8 + `x_out` 8 + `psum_mid` 24 + `psum_out` 24 = 64 位，4 个 PE 共 256 位。
   - 顶层：`w_cnt` 2 + `x_valid_d` 1 + `vld_sr` 8 + `done` 1 + `y_out` 24 = 36 位。
   - 合计 256 + 36 = **292 位**。
2. **把每个触发器归属到 RTL 寄存器**：读取综合后的 JSON 网表 `synth/out/systolic_row_synth.json`，取每个触发器 Q 端所在的网线，在该网线的所有别名中找到对应的 RTL 寄存器名（例如顶层的 `psum_bus` 与 `g_pe[0].u_pe.psum_out` 是同一组网线，归属到后者）。227 个触发器全部归属成功，没有无法归属的。
3. **逐个寄存器比较 RTL 位宽和保留的触发器数**，结果见 3.2。
4. **交叉核对**：按寄存器求和必须等于 yosys `stat` 给出的触发器总数，按类型求和也必须一致（见 3.3）。

### 3.3 交叉核对

- 按模块求和：PE0 8+8+16+16 = 48，PE1 8+8+17+17 = 50，PE2 8+8+18+18 = 52，PE3 8+0+19+19 = 46，顶层 2+1+8+1+19 = 31；合计 48+50+52+46+31 = **227**，与 `stat` 一致。
- 按类型求和：带使能的 `$_DFFE_PN0P_` = 4 个 `w_reg` 32 + `w_cnt` 2 + `y_out` 19 = **53**，与 `stat` 一致。这三类正好是 RTL 中带条件写入的寄存器（`if (w_load)`、`if (vld_sr[LAT-1])`）。其余 227 − 53 = **174** 个为 `$_DFF_PN0_`，与 `stat` 一致。

### 3.4 65 位差额的去向

| 原因 | 位数 | 说明 |
|---|---|---|
| 部分和高位恒为 0 | 57 | PE0 两级各去 8 位，PE1 各去 7 位，PE2 各去 6 位，PE3 各去 5 位，`y_out` 去 5 位：(8+7+6+5)×2 + 5 = 57 |
| 未使用的输出 | 8 | PE3 的 `x_out` 不接任何负载，整体去掉 |
| 合计 | 65 | |

部分和高位能去掉的原因：PE0 的上游部分和是常数 0，所以 PE0 的和只有 16 位乘积那么宽；之后每经过一个 PE，再加一个 16 位乘积，宽度最多多 1 位。所以 PE0..PE3 依次保留 16、17、18、19 位，`y_out` 跟 PE3 一样是 19 位。去掉的高位在网表中接常数 0，对外接口仍是 24 位。

PE3 保留了 19 位，比满量程 260100 实际需要的 18 位多 1 位。yosys 是按加法器操作数的位宽推算的，不是按数值范围推算的，所以没有去掉这一位。

## 4. 锁存器检查：无

- 网表中锁存器/SR 类单元（`$_DLATCH_*`、`$_DLATCHSR_*`、`$_SR_*`、`$dlatch`、`$adlatch`、`$dlatchsr`、`$sr`）数量为 0。
- `synth.ys` 中对这些类型执行了 `select -assert-none`，如果存在任何一个，yosys 会报错停止；本次通过。
- 过程转换阶段，所有 9 个过程寄存器都被转换为 `$adff`（异步复位触发器），没有生成锁存器。9 = `systolic_row` 5 个 + `mac_pe` 4 个，按模块计（展平前，`mac_pe` 只处理一次）。
- 原因：设计中所有 `always` 块都是时序块（`posedge clk or negedge rst_n`），没有组合 `always` 块，不存在推出锁存器的条件。
